# Cross-Platform Awareness

Applies to every task. This fork maintains **Rust Core (`core/`) and Android (`android/`) only** (`ios/` has been removed and upstream iOS changes are stripped during `just sync-upstream`). Never create `ios/` files or require iOS parity; keep Core and Android strictly aligned on shared contracts.

## Rules

1. Regenerate and verify Android when a `core/` change affects UniFFI interfaces or configuration, generated models, platform build inputs, or app-side integration; use [Quality Checks](quality-checks.md#closing-matrix) for commands. Internal Core changes preserving these contracts need Core checks only. Generated enum variants require generation and exhaustive handling in Android. A new variant the backend returns, such as a fiat provider or currency, ships disabled until the app release that decodes it has rolled out, because shipped apps fail on the whole response. If generation's effect is unclear, stop and restate before adding changes.
2. Never write a catch-all branch over a Core enum. A Kotlin `else ->` on a type Core owns turns the next variant Core adds into silent wrong behaviour; listing every variant makes the compiler name every place that still has to decide. Group the variants that share an outcome into one arm rather than reaching for the catch-all. This applies to a boolean or optional query over the enum just as much as to a label map.
3. Never edit generated files directly. Files headed `// Generated by` come from `core/` — change the source, regenerate, and commit the regenerated output when that generated area is tracked. Generated file locations:
   - **Android**: `gemcore/src/main/kotlin/com/wallet/core/primitives/generated/` (generated models), `core/gemstone/android/gemstone/src/main/java/uniffi/` (local ignored UniFFI bindings, generated by the `:gemstone` Gradle module at build time)
   - **Pattern**: any file with a `// Generated by` header or under `uniffi/gemstone/`
4. Run `just localize` when changing shared localization inputs in `localization/app/*.ftl`. Hardcoded user-visible strings are a bug.
5. Read chain capabilities from core's `ChainConfig` (`core/crates/primitives/src/chain_config.rs`). Hand-written per-chain capability lists in app code are forbidden — they drift from core.
6. Keep feature modules aligned with product pages. A feature module is one product area with one page, `docs/product/<name>.md`, carrying the same snake_case name (`features/<name>`, [`docs/product/`](../docs/product)), whose `presents` and `viewmodels` packages are `com.gemwallet.android.features.<name>.presents` and `.viewmodels`. A component several areas use lives in the shared `ui` module, not in `features/`; the QR scanner is the one shared feature module. Types inside a feature follow [ARCHITECTURE § Names](../docs/ARCHITECTURE.md#names).
7. Text sizes come from the type scale, never an in-between size. Text that shrinks to fit stops at a size from that scale.

## Generated Mocks

Shared data mocks exist once per type in [remote_types.yml](../core/bin/generate/remote_types.yml). Register generated models and Gemstone records or enums under `mocks:` there, then run `just generate-models`; never hand-write those mocks. Each field is a defaulted parameter in declaration order: empty strings/collections, zero, false, absent optionals, the first enum case, the epoch, or the nested type's mock. Enum mocks use the first case with default payloads. Generation fails and names unsupported fields; register their type or use an override when the default would be invalid.
